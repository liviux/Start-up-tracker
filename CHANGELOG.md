# Changelog

All notable changes to this project are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

## [0.3.0] - 2026-10-29

### Added
- Company templates now cover 199 countries and territories, with the major private, public and partnership forms for each. The new templates carry official register and tax authority sources, setup steps, recurring obligations, profile fields, people roles, expense categories and a document template; where an official page does not settle a fee or a date, the step says "check locally".
- The company template picker puts the country of the current template first, so the longer list opens near where you were.
- Twelve layout themes replace the palette-only ones. Studio stays the default; ten more, two each from five design skills, change the layout and type as well as the colours, and Coda adds a right-hand rail, ivory paper and a serif voice. Settings and the setup show a Calendar screenshot of each theme.
- "Try themes live" in Settings > Appearance opens a small bar at the top of the screen with a key per theme, so you can switch themes while you use the app.

### Changed
- The Company tab's coverage note and the README and docs now describe the full country list instead of the first 18 templates.
- Algeria, Central African Republic, Chad, Congo, DR Congo, Egypt, Equatorial Guinea, Gabon, Libya, Morocco, Sao Tome and Principe, South Sudan and Sudan use their final official register, tax and social security sources.
- A theme saved under an older palette id opens the layout theme that carries its idea, instead of falling back to Studio.
- Settings > AI agents shows the version an agent reported in its last check. Before a check, an npm or uv agent shows the registry version and a native program shows none, because the registry may not match what is installed.

### Fixed
- `startup-tracker autostart on` keeps your `PATH` in the systemd unit or LaunchAgent. Services otherwise start with only the system folders on `PATH`, so Settings > AI agents missed agents installed in `~/.local/bin`, `~/.bun/bin`, `/opt/homebrew/bin` or through nvm (Claude Code, Codex, Grok, Antigravity), and their adapters could not start them. Run `startup-tracker autostart on` again to update an existing service.
- When the tracker stops, it waits for agents of finished runs to stop too, instead of leaving them running for a few seconds.

## [0.2.1] - 2026-10-28

### Fixed
- Settings > Startups keeps long startup names, the record and media numbers and the row actions inside the panel instead of overlapping; narrow panels show the list as cards.
- Rename, Archive or Unarchive, Delete and Open in that list are icon buttons with tooltips and accessible labels, so all four fit on one row.

## [0.2.0] - 2026-10-28

### Added
- The version at the bottom of the sidebar opens a changelog window with the newest releases and a link to the full file on GitHub.

### Changed
- The category library no longer repeats events, partnerships, awards, associations or media across Marketing and Programs. Events, awards and associations live in Programs; media and PR work lives in Marketing; webinars and meetups you run yourself sit under Marketing content and your own community. Store and registry listings stay separate from marketplace seller programs, and the grant, prize and tax labels now say whether they mean the program or the money received.
- The demo startup now has a full set of linked marketing, program, funding and company records, two funding rounds and a UK Ltd company profile, and the README and documentation use ten screenshots of it.
- The setup's company template picker groups templates by country, and the Links step opens one link row at a time with a Cancel button.
- The setup's AI agents step uses a themed command dialog, clearer option groups and separators, and says that models appear after Check.
- Automatic backups default to six hours apart, and the interval can be set to any whole number of hours in the setup and in Settings > Backups.
- The calendar's startup switch sits beside the page title, its arrows are smaller and grouped, and the calendar filter explains its sections, date types and statuses.
- Calendar day and month counts keep their numbers and section colours without the M, P, F and C letters.
- The Programs tab reads "Programs &" over "Opportunities", so the section dot lines up with the other tabs.

### Fixed
- The open search field no longer draws a second blue focus box inside it, and the sync status is smaller.
- The update check says when GitHub's hourly limit for your network is used up, instead of "GitHub answered 403".
- The Generic company template no longer says it was checked against its sources on "?".
- AI agents installed as native commands (Codex, Claude Code, Grok, Antigravity, Command Code and OpenCode) are found during setup and in Settings, instead of only Copilot and OpenCode.

## [0.1.0] - 2026-10-21

The first public release.

### Added
- A clean starting point: the app starts empty, with neutral defaults and no example records, plus a leak check (`tools/check-leaks.js`) and a pre-commit hook that runs it.
- `npm start`, `npm run dev`, `npm test` and `npm run check`; demo data for a fictional startup (`tools/demo-data.js`); CI on Node 22, 24 and 26.
- Dates are calculated the same way in every time zone, and a translation layer prepares the interface for more languages.
- Several startups in one tracker, each with its own records, media, history and address (`/s/<id>/`), a switcher that marks startups with unsynced edits, and search and calendar across all startups. An older one-tracker database is upgraded into a startup named "Imported" after a copy of it is kept.
- Settings replaces the Config drawer: startup profile, startups, appearance, general settings, backups, recycle bin and About. Backups now include media files (stored once), come in three kinds with their own rotation, and restore one startup, the whole database or selected records after a safety backup. Export and import as zip, JSON or a database file. The recycle bin covers every record type and empties itself after 30 days.
- One status list for every section and every startup: four groups (Planned, In progress, Done, Closed) and 22 statuses that you can rename, describe, reorder and extend in Settings > Statuses, plus a separate list for campaigns. Badges, dropdowns, header counts and one shared status filter follow the groups. A status the list does not know is kept and shown as "Unmapped" instead of being reset to the first one.
- Section colours: Marketing, Programs, Funding and Company each have a colour (Company moved from orange to violet), shown in the sidebar, page headers, chips, search results and the calendar, always next to the section code. Settings > Appearance offers a colour-blind friendly palette and your own colours, with text kept readable at 4.5:1.
- The calendar shows per-day counts per section (`M2 P4 F1 C1`), a real month of five or six weeks, section and event-type toggles next to the status filter (remembered per startup), deadlines, milestones, commitments, Company entries with their real status and optional campaign dates. Events open in place with "Show in list". The summary has one row per section and status group, keeps items and events apart, and counts the visible days or all time.
- One category library for Marketing, Programs and Funding: categories, subcategories and types (Marketing gained the type level), brand-free and with a description on every entry. A target can sit in several branches, primary first, and is picked from a searchable tree. Extra > Categories edits the library for every startup (rename, describe, reorder, add, merge, delete with a move, reset, export and import, accept new library entries) and turns entries on or off per startup. Unknown or turned-off categories stay on the targets that have them.
- Links between any two records of a startup (related, uses, feedback about, blocks, follow-up of, funds), shown on both records and picked from one searchable dropdown that pages through long lists, groups results by kind and works with the keyboard. It replaces the long lists for media "Used in", the media filter, linked media and programs, the feedback target, "Link feedback", "Blocked by" / "Blocks" and the payment's program. Older link fields become links the first time a startup opens. Links to records in the recycle bin are hidden until they come back, and go when the record is deleted for good. Prompt scopes and a target row's categories use the category tree.
- One target window for Marketing, Programs and Funding, with the same six tabs (Overview, Edit, Details, Links, Extras, History) and the same basics in every section. Every field comes from a registry with help text, examples that are never saved and suggested values you accept with "Use"; empty and 0 stay apart in number fields. The update log, milestones and deadlines exist in every section, Programs keep one documents checklist, and Funding commitments and payments are edited in the same window. "Add and open details" opens a new target in the window before it is added. Extra > Fields adds your own fields, shared by every startup. Older fields with one clear new home move there once; everything else is kept and shown under "Other fields".
- Marketing, Programs and Funding pages look and work the same: header numbers per status group plus the money each section tracks, one Focus queue ("On this day" and "Due by", like the calendar), the same Add target form with "Add and open details", and a read-only Targets table with the same columns, saved views, filters and paging. A row or its name opens the target window; there is no inline editing and no Actions column. Funding rounds sit below the Funding targets.
- Extra in a new order (AI, Prompts, Media, Feedback, Research links, then Customize: Campaigns, Tags, Categories, Fields), with the same header on every page: name, count, filter and Add. Campaigns, tags, the AI page and research links ticked "Shared" belong to every startup and are saved straight away, reloading instead of overwriting when another tab changed them first. The AI page starts empty, adds subscriptions and APIs, and has an editable exchange rate that shows when it changed. Media can be copied to another startup, filtered by what it is linked to and by tag, and keeps its file while it sits in the recycle bin; `tools/media-orphans.js` lists files nothing uses. Feedback lists are generic and editable, with three blocks of extra fields (person and context, journey, assumption test). Media types, feedback lists, research link groups and the Programs documents checklist are edited in the app and shared, and no longer copied into the page. Tags can be renamed, merged and deleted across all startups, have a colour, and show where they are used; the generic default tags are added once. A campaign lists its targets in every startup.
- Prompts are shared by every startup and fill in each startup's own details. The preset bar is always visible, grouped by section, with 21 generic presets and two built-in prompts ("Target research and creation", "Outreach and strategy plan") drawn from an example library; presets whose categories are off are hidden. Only double braces are variables, and an empty variable takes its line (and a block's heading) with it. A prompt copied for an agent carries a 24-hour token that can only add and update targets of that startup; the master token never appears in a prompt. Chat replies can be pasted into "Import AI results", which checks them against the fields and flags likely duplicates. Your edits of a built-in prompt can be reset to the shipped version, and prompts, presets and examples export and import as a JSON pack. Settings > Startup profile gets an editor for the company and founders text (`{{CONSTRAINTS}}`) with a counter and topic tips. Adding a record no longer sends a reorder of its whole section, so it no longer conflicts with another writer adding to the same section.
- The SRL tab becomes **Company** (COMP), driven by 18 company templates for the ten largest economies (without Russia) and Romania, plus Generic for any other country or legal form. Every step and obligation names its official source and the date it was checked, or says "check locally". Profile holds the template, region, incorporation, conditions, fields, any number of people and bank accounts; Setup and Obligations list steps and the next twelve months of deadlines with real statuses, worked out from the template's rules; Expenses compares this month's spending with a monthly budget in the startup's currency; Document gives a Markdown summary, in Romanian or English for the Romanian template. Steps, obligations, deadlines and expenses are records with history, conflict handling and the recycle bin, and appear in the calendar and the search. National ID numbers and bank accounts are stored masked, read only through their own route, never given to agents or prompts, and left out of exports unless you tick them. A template update changes only its text, never your dates or statuses.
- **AI agents**: set up Claude Code, Codex, Gemini CLI, OpenCode or any other agent that speaks the Agent Client Protocol in Settings > AI agents, from the official ACP registry (fetched once a day, with a shipped copy and a built-in list as fallbacks) or as a custom command, always after confirming the exact command. "Check" says whether an agent is ready, needs a login, is incompatible or not installed, and lists its models. "Run with…" on the Prompts page runs a prompt with an agent and model and shows it live: conversation, prompt, changes, permissions and a redacted log, with cancel, follow-up messages and run again. Agents save through tracker tools (an MCP server with one token per run) that search, create, update and link targets but never delete; each change is in the history under the run and "Undo this run" takes them back. Permission requests follow a per-agent policy (allow everything, research only, ask me). The sidebar's Agents page lists every run with a badge for runs going and waiting.
- Every string of the interface comes from `content/i18n/en.json`, about 1,050 more than before: the page markup, `app.js` and the target window, section pages, field editor and item picker. Counts use real plural forms. `?pseudo-locale=1` shows each string as its key, so missed text stands out, and `npm run check` flags new hard-coded text. Wording is in sentence case throughout. Tooltips open on keyboard focus, Tab stays inside the target window, and every control has a name. Removed: the "null" shown in Categories and Settings > About, leftover styles of the old Insights tab and of tabs that no longer exist.
- Your data lives in `~/.startup-tracker` (`%USERPROFILE%\.startup-tracker` on Windows) unless `--data-dir` or `STARTUP_TRACKER_HOME` names another folder; `npm run dev` keeps `~/.startup-tracker-dev`. The first start creates the folder readable by you only and prints where it is. A test run refuses the default folder, so tests and tools never reach real data by accident.
- **The setup**: the first time the tracker opens, a setup in the browser asks for your time zone and the startup's name (the only two required fields), then its profile and icon, company template, links, AI context, which categories to track per section (Recommended ones ticked, Skip keeps them), AI agents and backups. Each step is saved, so it continues where you left it after a reload, and a "Finish setup" badge stays in the sidebar until it is done. It ends with "Add another startup", a fictional demo startup you can add and delete in one click, or "Open the tracker". Settings > Startups runs the startup steps for a new startup, and Settings > About has "Run setup again". The top-bar Links menu now lists the startup's links, with brand icons for about 30 link types (Tabler Icons and Simple Icons). Automatic backups can be turned off.
- **Install and the `startup-tracker` command**: one line installs a release (`install.sh` for macOS, Linux and WSL, `install.ps1` for Windows), after checking Node.js 22.16 and the archive's SHA-256, into `~/.startup-tracker/app`, adds the command and can start the tracker at login (systemd, launchd or Task Scheduler). The command starts, stops and reports on the tracker, shows its log, takes and restores backups, updates to the latest release after a safety backup (and rolls back if the new version does not start), checks the install (`doctor`) and uninstalls without touching your data unless you type DELETE. The port, 57322, is saved at the first start and never changes on its own; a taken port is reported with the offer to save another. Settings > About shows whether a newer version exists and can check now; the daily check follows the network switch. `start.sh` and `start.bat` now run the command. `tools/build-release.js` builds the release archive. The tracker needs nothing but Node.js.
- Documentation and project files: a README with the install lines and a screenshot of demo data; a documentation site in `docs/` (Docsify, served from the repository's own files with no CDN, with search) with new pages for concepts, privacy (what leaves your computer), AI agents and safety, and FAQ and troubleshooting, plus the install scripts for the short URLs; CONTRIBUTING.md, CODE_OF_CONDUCT.md (Contributor Covenant 2.1), SECURITY.md, THIRD_PARTY_NOTICES.md, issue and pull request templates and Dependabot. A release workflow tests on Linux, macOS and Windows, refreshes the ACP registry snapshot, checks that every catalog agent's package or download still exists, builds the archive with its checksums, scans it and the repository for leaks, and publishes the release with notes from this file. Agent icons in Settings > AI agents load only while the network switch is on.

### Security
- The local server accepts changes only from the tracker page or with the API token, serves only the app's own files, keeps uploads inside the media folder and sends a strict content security policy. The old whole-state save route is gone.
